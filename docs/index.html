macOS only Free & open source

Files that are the wrong format, or far too large.

One command on your Mac. It converts images, documents and data, strips backgrounds using the same engine as Preview, and compresses video. Point it at a single file or a whole folder; it never touches your originals.

$ npm install -g my_media_automations
Read the source

Needs macOS 14 or newer and Xcode Command Line Tools (xcode-select --install). ffmpeg only if you touch video or audio.

One

What actually lands on your machine

A 56 KB package with nine dependencies. The two hard parts, cutting a subject out of a photo and rendering a PDF, are done by frameworks already on your Mac. No Chromium to download, and no 170 MB machine-learning model.

Apple's Vision framework does the masking

Background removal calls VNGenerateForegroundInstanceMaskRequest, literally what Preview's “Remove Background” uses. Offline, no API key, about a second for a 4032×3024 photo.

WebKit renders the PDFs

Documents are laid out and printed by the same engine as Safari, paginated onto A4 rather than dumped onto one endless page.

Two small Swift helpers, compiled on first use

They ship as source, not binaries, so nothing prebuilt can mismatch your Mac, Apple silicon or Intel. That is what the Command Line Tools are for.

Nothing phones home

No account, no upload, no telemetry. Your files never leave the machine, which is the whole reason to prefer this over a website that wants your photo.

Two

Your first run

Type auto. You get a menu of the four tools; arrow keys and enter. Everything below is the real output, not a mockup.

The wordmark animates on launch: a glint sweeps across it once, then the menu opens.

Or skip the menu entirely

Name a tool and its arguments go straight through. Handy in a script, or when you have done it once already and remember what you want.

Answer nothing, or answer everything

Leave arguments off and it asks. Pass them all and it asks nothing. Formats are multi-select — space toggles, or comma-separate them on the command line.

passthrough 
$ auto convert notes.md docx,pdf      # two documents, one pass
$ auto compress ~/clips normal,ultra  # an archive copy and a share copy
$ auto bg photo.heic transparent      # cut out, alpha kept
$ auto image ~/Downloads png,webp     # both formats
Three

Images and video, format to format

24 image formats in, including HEIC and camera RAW from most brands, plus 21 video containers. Video is normalised to MP4.

auto image 
$ auto image IMG_1335.HEIC png,webp
│
◒  [1/2] IMG_1335.HEIC -> .png — decoding with sips [0s]
◇  ✓ IMG_1335.HEIC -> IMG_1335.png   21.6 MB
◇  ✓ IMG_1335.HEIC -> IMG_1335.webp  3.1 MB

It tries three decoders before giving up

sharp first, then macOS sips, then ImageMagick if you have it. That cascade is why HEIC and RAW work where a single library would fail.

SVG asks what you mean

Wrapping the pixels is not the same as tracing vector paths, so it offers both, plus two stylised traces. Tracing needs vtracer.

Four

Cutting the subject out

Point it at a photo, or a folder of them. Output is PNG with a real alpha channel, or flattened onto any colour you name, and you can ask for several at once.

auto bg 
$ auto bg photo.jpg transparent,white
│
◇  1 image detected
◒  [1/2] photo.jpg -> transparent — detecting subjects [0s]
◇  ✓ photo.jpg -> photo-transparent.png
◇  ✓ photo.jpg -> photo-white.png
│
└  Done! Files saved to no-bg/

Every file says which setting made it

photo-transparent.png, photo-white.png. Variants can never overwrite each other, and asking for a new background is never mistaken for work already finished.

Phone photos come out upright

EXIF orientation is applied before the mask, so a portrait HEIC does not arrive on its side. Images with no subject are reported as skipped, not as failures.

Headings become real headings

# through ###### map onto Word's own Heading 1–6 styles, so the navigation pane and a table of contents actually work rather than the text merely looking bigger.

A4, and properly paginated

Both .docx and .pdf come out A4 with 2cm margins. Tables and code blocks are kept whole across page breaks, and a heading is never stranded at the foot of a page.

Markdown survives the round trip

md → docx → md comes back intact for headings, tables, lists, links, bold, and both fenced and inline code. The project's own 300-line readme was the test case.

GIFs get two passes

A palette is built from the clip, then the clip is encoded against it. One pass falls back to the 216-colour web palette and bands visibly.

Long encodes count up a real percentage, so a slow job never looks like a hang.

It refuses a bad trade

If a file would shrink by less than 5%, the result is thrown away and your original kept. You get already well compressed instead of a slightly worse file for nothing.

Formats stay put

A compressor that quietly turns your PNGs into JPEGs is a nasty surprise. Video becomes H.264 and AAC, which plays everywhere. Nothing is ever upscaled.

Seven

The habits that make it safe to run twice

The parts you stop thinking about after a week, which are the parts that matter when you point a batch tool at a folder you care about.

Your originals are never modified

Results land in a sibling folder beside whatever you pointed at: converted/, no-bg/, compressed/.

Running it again does nothing

Work whose output already exists, and whose source has not changed since, is skipped. Edit one file and only that one is redone.

One failure never stops the batch

A file that cannot be read is reported and the run continues, with a tally at the end: how many done, how many skipped and why, how many failed.

~ works everywhere

In the shell, and typed into a prompt where no shell is there to expand it. Press Ctrl-C at any question to leave cleanly.

Why not just use a website?

The free converters in a browser tab are genuinely convenient, and for one file they are hard to argue with. The differences below are structural, not marketing: they follow from where the work happens.

Uploading to a converter site
Running on your machine
Your file goes to someone else's server, and their retention policy becomes your problem.
Nothing leaves your disk. No account, no upload, no telemetry.
A 4K clip travels up and comes back down before you can use it.
The bytes never move off the SSD, so there is no round trip to wait through.
Usually one file at a time. Real batching tends to sit behind a subscription.
Point it at a folder. Forty files is the same command as one.
Free tiers cap file size, watermark the output, or meter you per day.
No caps, no watermark, no metering. Your free disk space is the limit.
You cannot put a browser tab inside a shell script.
It composes: a Makefile, a git hook, a cron job, a build step.
Whatever encoder the server happens to run, at whatever settings.
The frameworks already on your Mac, the ones Preview and Safari use.

Against a paid Mac app

A good native app wins on anything visual: previewing a crop, nudging a mask by hand, comparing two exports side by side. It costs money, and it still cannot be called from a script. Different tools, different jobs.

When a GUI is the better choice

If you need to see the result before committing to it, or to adjust one image by eye, open Preview. This is built for the case where you already know what you want and there are thirty of them.

Worth knowing before you do

  • macOS 14 or newer only. The Vision API it depends on arrived in 14, so npm refuses to install it on Linux or Windows rather than failing strangely later.
  • Xcode Command Line Tools are required (xcode-select --install) because the two Swift helpers compile on first use.
  • ffmpeg is needed for video and audio only. Everything else is built in.
  • Only the first sheet of a multi-sheet .xlsx is converted. It warns you when it sees more.
  • npm audit reports one moderate advisory reached through exceljs, which has no newer release. Only .xlsx conversion touches that dependency at all.
